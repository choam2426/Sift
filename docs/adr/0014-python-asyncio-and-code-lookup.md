# Python·asyncio로 구현하고 코드 조회는 tree-sitter로 시작한다

2026-09-27 결정.

## 언어와 병렬 처리

Sift는 Python과 `asyncio`로 구현한다. 처리 시간 대부분은 Jev와 에이전트 호출 대기이고 실제 한계는 요청 속도 제한과 비용이므로, I/O 동시성으로 충분하다. CPU를 쓰는 파싱은 tree-sitter(C 구현) 안에서 돌고 CodeQL·Ghidra는 별도 프로세스다. 파싱이 병목이 되면 파일 단위 프로세스 풀로 나눈다. tree-sitter, Ghidra 연동, 모델 SDK와 기존 실험 자산이 Python에 있고, 단일 바이너리 배포는 사내 CLI인 [v0.1.0](0012-v0.1.0-first-release-scope.md)에 필요하지 않다.

동시 요청 수 제한, 예산 상한, 과금·인증 오류(HTTP 402 등) 시 즉시 정지는 Jev 클라이언트 한 곳에 둔다. 2차 실험의 크레딧 소진은 이 제어가 없어서 생겼다.

재검토 조건: 로컬 분석이 실제 병목으로 측정되면 그 부분만 다른 언어로 옮긴다.

## 코드 조회

코드 조회는 하나의 인터페이스(함수 목록, 본문, 호출자·피호출자, 선언)로 정의하고, v0.1.0 구현은 tree-sitter로 한다. 디컴파일 결과는 같은 인터페이스의 다른 구현으로 붙인다.

CodeQL은 제품 구현에 쓰지 않고 **관계 추출의 비교 기준(상한)**으로만 쓴다. 바이너리를 다루지 못해 별도 구현이 어차피 필요하고, 무료 사용 조건이 OSI 공개 소스 분석으로 한정돼 사내 비공개 대상에 쓸 수 없으며([ADR 0006](0006-codeql-source-relation-experiment.md)), 7-Zip 실험에서도 함수 포인터는 풀리지 않았다. 2차 묶음은 순위를 매길 만큼만 맥락을 담으면 되고 부족한 부분은 3차 에이전트가 조회하므로([ADR 0010](0010-three-stage-structure.md)) 정밀한 관계 그래프가 결정적이지 않다.

구현과 함께 라벨 사례로 **묶음의 필수 줄 포함률**을 tree-sitter와 CodeQL에서 비교한다. tree-sitter가 필수 맥락을 눈에 띄게 더 놓치면 CodeQL이 아니라 libclang으로 바꾼다. libclang은 라이선스 제약이 없고 매크로를 정확히 처리한다. 1차 실험에서 Expat 매크로의 tree-sitter 파싱 오류가 있었던 것이 이 위험의 신호다.
