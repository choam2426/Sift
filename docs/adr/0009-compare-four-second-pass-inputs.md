# 2차 후보 입력의 네 가지 구성을 모두 비교한다

> 재검토 상태: 2026-09-27 [ADR 0010](0010-three-stage-structure.md)에서 2차의 역할을 **1차 통과 함수의 재선별**로 정하고 [ADR 0011](0011-vulnerability-type-profiles.md)에서 유형별 질문을 프로파일로 분리했다. 이에 따라 네 방식이 독립 후보를 만들어 3차 대상을 늘리는 아래 비교는 새 구조의 실행 계획이 아니다. 출발 함수당 하나의 묶음을 만드는 [대안](../../experiments/archive/second-pass/README.md#출발-함수당-이해-맥락-묶음--2026-09-27-제안)은 아직 제안이다. 기존 4×5 요청·응답은 비교 기록으로 보존한다.

2026-09-27 결정. 2차 후보를 호출 흐름·값의 흐름·상태 변화·관찰 가능한 효과를 중심으로 구성하는 네 가지 안을 모두 실험한다. 구현 전에 일부 안을 제외하지 않고, 같은 소스 스냅샷과 1차 출발점에서 필요한 근거의 포함·누락, 중복, 비용과 동일한 3차 조사 예산에서의 검증 성과를 비교하기 위해서다.

입력 구성끼리 비교할 때는 Jev 모델·질문·반복 조건과 3차 모델·조사 예산을 맞춘다. 후보 수와 경계가 다를 수 있으므로 후보 점수를 일대일로 대응시키거나 Noul의 상승만으로 우열을 정하지 않는다. 크기를 이유로 함수를 제외하거나 본문을 자르지 않으며, 실제 입력 한도 초과와 미평가는 결과에 남긴다.

같은 날 네 입력 구성에 안전 조건 위반·함수 사이 계약 불일치·검사와 사용의 불일치·상태 전이의 불일치·구체적인 실패 기전이라는 다섯 질문을 교차한 **4 × 5 = 20개 실험 조건을 모두 비교**하기로 했다. 다섯 질문은 조사 가치보다 코드가 뒷받침하는 실제 보안 관련 실패 여부를 묻는다. 이는 요청 20건을 뜻하지 않으며 각 조건에 사례별 후보와 반복이 포함된다. 구체적인 후보 구성 규칙·실험 사례·반복 횟수·예산·질문의 정확한 문구는 [비교 설계](../../experiments/archive/second-pass/design-comparison.md)에서 확정할 제안으로 남긴다.

2026-09-27 추가 확인: 네 입력 방식은 **각각 독립적으로 후보 경계를 생성**한다. 같은 출발 함수가 방식에 따라 서로 다른 수와 범위의 후보를 만들 수 있다. 따라서 후보를 공통 앵커에 억지로 맞추지 않고, 같은 사실 스냅샷·질문·3차 조사 예산에서 전체 생성·선별 성과를 비교한다.

2026-09-27 실행 범위 확인: 첫 7-Zip 26.01 비교는 지정한 55개 C 파일에서 1차를 통과한 **376개 함수 전체**를 네 방식의 공통 출발점으로 사용한다. 일부 출발점에서 특정 방식의 후보가 생성되지 않는 것도 누락으로 기록한다. Jev 호출 횟수가 크다는 이유로 출발점이나 후보를 샘플링하지 않는다. 이 범위는 7-Zip 전체 소스나 다른 언어 사례까지 완료했다는 뜻은 아니다.
