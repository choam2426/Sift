# Sift 비교군에 2차 Jev 재선별을 복원한다

2026-10-02 결정. Sift 주 비교군은 [원래 3단계 구조](0010-three-stage-structure.md)대로 **1차 함수 전수 선별 → 2차 관련 코드 후보 재선별 → 3차 에이전트 심층 분석·검증**을 실행한다. [ADR 0022](0022-first-comparison-uses-one-jev-stage.md)의 1차 단독 구성은 Sift 주 비교군에서 제외하고, 각 단계의 기여를 분리할 때 쓰는 절제 비교군으로 남긴다.

## 결정 근거

CyberGym Level 0 `arvo:10400` 파이프라인 파일럿에서 1차 단독 구성은 22,825개 함수 중 3,425개를 선택했다. 실제 취약 파서를 포함하는 `ReadMNGImage`는 점수 0.87, 63위로 선택했지만, 패치 대상 헬퍼 `mng_get_long`은 점수 0.65, 9,610위로 선택 밖이었다. 추출된 호출 기록에는 `ReadMNGImage`에서 `mng_get_long`으로 가는 직접 호출이 24곳 있어, 피호출자를 포함하는 2차 묶음이면 이 헬퍼를 시작 패킷에 넣을 수 있었다. 에이전트는 1차 순위만 받고 이 헬퍼의 결함까지 좁히지 못한 채, 취약판과 수정판에서 모두 종료되는 다른 `ReadMNGImage` 경로를 최종 PoC로 제출했다. 같은 과제의 기본 에이전트 파일럿은 `mng_get_long`의 힙 범위 초과 읽기를 재현하고 수정판 교차 검증을 통과했다.

이 한 사례는 2차의 효과를 입증하지 않는다. 그러나 함수 하나의 점수를 최종 조사 목록으로 바로 쓰는 구성이 관계에 있는 결함을 놓칠 수 있고, 그 구성이 이 프로젝트가 정의한 Sift의 3단계 구조를 구현하지 않는다는 점은 확인했다. 따라서 2차를 생략한 실행을 Sift 전체의 성패로 해석하지 않는다.

## 실행 계약

- 1차는 대상의 모든 분석 유닛을 Jev로 평가하고 결정적 규칙으로 출발점을 고른다.
- 2차는 모든 1차 출발점에 대해 미리 고정한 관계 규칙으로 후보를 만들고 Jev로 다시 평가한다. 출력에는 후보 순위뿐 아니라 출발점, 포함한 코드, 넣지 못한 관계와 미해결 호출을 담은 시작 패킷을 남긴다.
- 3차 에이전트는 2차 순서와 시작 패킷에서 출발하되 저장소 전체의 관계를 계속 추적하고 PoC를 독립 검증한다.
- Sift군의 에이전트가 대상에 맞는 두 Jev 단계를 직접 구축하고 실행한다. 사전 계산한 점수나 순위는 주지 않는다.
- 함수 추출, 두 Jev 단계, 후보 구성, 에이전트 조사와 검증에 든 시간·요청·토큰을 모두 종단 비용에 포함한다.
- 1차 단독 구성과 2차 포함 구성은 별도 실험군으로 표시한다. 전자를 `Sift`라고 부르지 않는다.

2차의 관계 규칙, 질문, 입력 한도와 선별 예산은 취약점 유형과 대상에 따라 벤치로 정하고 실행 전에 고정한다. 과거의 묶음 전체 점수 실험은 1차보다 나아지지 않았으므로 그대로 기본값으로 채택하지 않는다. 첫 C/C++ 메모리 안전성 구성은 [ADR 0026](0026-prioritize-callsite-candidates-and-adaptive-expansion.md)에서 호출지점 중심 문맥의 가치, 같은 후보에서 Jev 재순위의 기여, 고정 확장 대비 적응형 확장의 기여를 차례로 검증하기로 했다.
