# 2차 묶음은 Jev의 판별력에 맞추고, 규칙은 라벨 사례의 측정으로 정한다

2026-09-28 결정. [ADR 0010](0010-three-stage-structure.md)의 2차(출발 함수마다 관련 코드 묶음을 만들어 Jev로 다시 평가)에서 묶음을 구성하는 원칙이다. 구체적인 규칙은 아래 실험으로 정한다.

## 원칙

- **묶음은 Jev가 판별하기 좋게 만든다.** Jev는 묶음 전체에 점수 하나를 주므로 관련 없는 코드는 신호를 희석할 수 있다. 2026-09-26 의미 관계 실험에서 넓힌 입력은 32k 한도를 넘었고, 초점을 좁힌 입력의 점수는 0.28에서 0.19로 내려갔다([기록](../../experiments/archive/second-pass/codedb-semantic-probe.md)). 에이전트는 코드를 더 조회할 수 있으므로, 에이전트용 시작 패킷은 묶음에 "넣지 못한 관계" 목록을 더해 준다.
- **첫 프로파일의 버그 모양을 따른다.** [입력 유도 값의 경계·정수 오류](0011-vulnerability-type-profiles.md)는 값이 들어오고(호출자 인자, 구조체 필드) 계산·검사된 뒤 메모리 연산에 쓰인다(피호출자). 출발 함수와 값을 주고받는 호출자·피호출자가 핵심이다.
- **값의 흐름은 경계가 아니라 우선순위로 쓴다.** 4×5 실험의 값 방식은 값마다 작은 후보를 만들다 맥락이 잘려 필수 코드를 담은 후보가 없었다. 관련 함수는 모두 후보로 두고, 값을 주고받는 것부터 넣으며, 한도에 걸리면 무관한 것부터 빼고 기록한다. 함수 본문은 자르지 않는다.
- **1홉에서 시작한다.** 1차 상위 15%에서 결함 지점이 빠진 사례 중 7-Zip(`XzUnpacker_Code` → `MixCoder_Code`)과 tar(`EntryFields::unpack` → `unpack_dir`)는 1홉이다. go-jose(`DecryptMulti` → `decompress` → `inflate`)는 2홉으로 추정되며 Go 관계 추출이 없어 확인하지 못했다.

## 규칙을 정하는 실험

좋은 묶음은 **도달**(버그의 필수 줄이 묶음 안에 있다)과 **판별**(버그를 담은 묶음이 더 높은 점수를 받는다)로 잰다. 도달은 라벨만으로 Jev 없이 잴 수 있다.

1. 규칙 후보를 만든다. A: 출발 함수 + 대상 안의 모든 피호출자. B: A + 호출자. C: A와 같되 출발 함수의 값을 받는 피호출자를 먼저 넣는다.
2. 라벨 사례에서 도달률, 묶음 크기, 한도 초과를 Jev 없이 비교한다.
3. 도달률이 좋은 한두 가지만 Jev로 판별력을 비교하고, 1차 순위만 쓰는 기준선과 비교한다.

라벨이 7-Zip 하나뿐이면 규칙을 한 사례에 맞추게 되므로, [설계용 라벨 사례](0013-evaluation-cases.md)를 먼저 만든다. 결론은 봉인 사례로 다시 확인한다.
