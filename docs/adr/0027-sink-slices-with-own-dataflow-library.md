# 2차는 싱크 역방향 슬라이스로 가고, 데이터플로우 라이브러리를 libclang 위에 직접 구현한다

2026-10-08 결정. 기존 묶음 방식(A·B·D·E)과 [ADR 0026](0026-prioritize-callsite-candidates-and-adaptive-expansion.md)의 호출지점 경계(P·R·C)를 배제하고 2차 구조를 다시 생각한 다섯 후보([제안 문서](../../experiments/second-pass/stage2-structure-proposals.md)) 중 **싱크 기준 역방향 슬라이스**를 첫 구현 대상으로 고른다. 이를 위한 데이터플로우 라이브러리는 `sift` 패키지 안에 **libclang AST 위에 CFG까지 직접 구현**한다. 사용자는 얕은 근사 슬라이서를 명시적으로 거부했고, 제대로 된 분석기를 요구했다.

## 왜 싱크 슬라이스인가

- CyberGym의 오라클은 sanitizer 충돌이고 충돌은 특정 위험 연산에서 난다. 후보의 단위를 위험 연산(싱크)으로 두면 후보 단위와 평가 단위가 일치한다.
- 지금까지의 반대 신호는 모두 "코드를 더 붙이면 나빠진다"였다. 슬라이스는 함수에서 무관한 코드를 빼고 값의 흐름만 남긴다.
- `arvo:10400`에서 1차가 놓친 `mng_get_long`은 4바이트 읽기 싱크에서 거슬러 오르면 `ReadMNGImage`의 청크 길이 검사 유무까지 한 슬라이스에 들어온다.

## 왜 직접 구현인가

- CodeQL은 질의·라이브러리만 MIT이고 C/C++ 추출기와 엔진은 비공개 CLI라 비공개 대상에 쓸 수 없다([ADR 0014](0014-python-asyncio-and-code-lookup.md)).
- Joern은 학술적으로 널리 쓰이지만 C/C++에서 전처리를 하지 않고 alias·간접 호출을 풀지 않으며, 이 저장소에서 조용한 누락(7-Zip `#include`된 `.c` 35개, 1000자 절단)을 확인했다.
- `sift.cfamily`는 이미 compile DB와 실제 헤더로 모든 `#if` 구성을 파싱해 함수와 호출지점을 정확히 갖고 있다. 슬라이스의 가장 치명적인 실패는 코드를 못 본 것이므로 이 입력 충실도가 결정적이다.

## 정한 것

| 항목 | 결정 | 기각한 대안 |
|---|---|---|
| 분석 수준 | libclang AST + 자체 CFG (Python) | clang libTooling 사실 추출(대상 컨테이너마다 C++ 도구 빌드 필요), LLVM IR(빌드 구성 하나만 보게 되어 [ADR 0002](0002-complete-unit-evaluation.md)·0014의 전 구성 원칙과 충돌, gcc 대상 재빌드 필요) |
| 정밀도 | 함수 내 흐름 민감, 접근경로(`v`, `v.f`, `p->f`, `*p`, `a[*]`) 필드 민감, 호출 그래프 SCC 순서의 요약 기반 절차간, 문맥 비민감, 간접 호출은 주소 취득 집합 + 시그니처로 해석하고 불확실로 표시 | 문맥 민감(k=1): 첫 효과 검증에 과함. 필드 비민감: 구조체 상태가 많은 파서에서 과대 포함이 큼 |
| 첫 산출물 | 싱크 역방향 슬라이스와 소스 순방향 오염 추적을 같은 엔진으로 | 역방향만: 역할 사슬·도달 경로 후보에 재사용하려면 어차피 필요 |

CFG는 if/else, 루프, switch fallthrough, break/continue, goto, return, 단락 평가, `?:`, 쉼표를 다루고 지배·후지배로 제어 의존을 계산해 검사 조건이 슬라이스에 들어가게 한다. 싱크와 소스, libc 모델은 데이터 표로 두고 호출자가 확장한다. 못 푼 관계(간접 호출, 모델 없는 외부 함수, alias, 깊이·라운드 한도, 토큰 예산 절단)는 슬라이스 출력에 명시하며 안전하다고 간주하지 않는다.

## 검증

- 테스트는 모델·네트워크 없이 `uv run pytest`로 돈다. 픽스처가 CFG 구조, 필드 민감, 요약, 간접 호출, 호출 경계를 넘는 슬라이스, 제어 의존, 모델, 구성별 사실, 예산 절단을 각각 덮는다.
- 개발 사례는 `arvo:10400`의 `mng_get_long` 읽기 싱크다. 슬라이스가 `ReadMNGImage`의 24개 호출지점으로 넘어가 청크 길이 정의와 검사(또는 검사 부재)를 담아야 한다. 호스트에서는 시스템 헤더가 달라 `png.c` 단일 TU로만 확인하고, 전체 실행은 CyberGym 이미지 안에서 한다. 이 사례는 설계 개발용이며 효과의 증거로 세지 않는다.
- 슬라이스가 라벨의 필수 줄을 담는지(과소 포함)를 먼저 재고, Jev 순위 효과는 그 뒤 사전 등록한 기준으로 본다.

## 아직 정하지 않은 것

싱크 집합의 최종 범위, 슬라이스 토큰 한도, 2차 질문, 슬라이스 순위와 1차 점수의 결합, 쌍대 비교(제안 3번)와의 결합 여부. 구현 결과를 보고 정한다.
