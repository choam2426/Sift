# 1차는 함수 본문만으로 조사 가치를 평가한다

Sift의 1차 기본안은 모든 함수의 전체 본문을 Jev에 각각 제공하고 `Is this function worth a security researcher's time to inspect further for bugs?`라는 단일 `Noul` 질문으로 조사 가치 순위를 얻는 것이다. 다른 함수 본문과 관계를 따라가는 일은 2차에 맡긴다. 1차에서 모든 버그 관련 함수를 직접 선발하려는 목표 대신, 빠르게 유망한 출발점을 남기는 목표를 택했다.

[파일 전체 표본 실험](../../experiments/first-pass/contrastive/README.md)의 공개 취약점 6개에서 이 질문은 각 파일 상위 10% 선발 시 세 반복 모두 5개 기전에 도달했다. 더 복잡한 대조 판단 질문은 3개, 함수 길이 기준은 4개였다. [선언 추가 실험](../../experiments/first-pass/declarations/README.md)에서 클래스·모듈 선언을 모든 함수에 붙여도 5개로 같았고 입력 토큰이 약 33% 늘었다. 두 실험은 `jev-1.13.0`에서 실행했다. 따라서 더 복잡한 질문이나 선언 추가를 기본안으로 채택할 근거가 없었다.

첫 구현에서는 성공적으로 평가한 함수 중 `Noul ≥ 0.60`인 것만 2차로 추출한다. 같은 277개 함수에서 이 기준은 반복별 40~42개(약 14~15%)를 통과시키고 알려진 6개 기전 중 5개를 남겼다. `0.65`도 5개였지만 통과한 취약 함수 하나의 점수가 `0.68~0.69`여서 여유가 작았고, `0.70`은 4개로 줄었다. 선별 기준에는 모델·질문·입력 표현의 버전을 기록하고 그 요소가 바뀌면 `0.60`을 그대로 적용하기 전에 확인한다.

이 수치는 여섯 개의 소스 코드 사례에서 얻은 결과이며 제품의 재현율이나 최적 성능을 뜻하지 않는다. 별도 탐색 표본에는 `0.54`를 받은 취약 함수도 있었다. 디컴파일 코드의 점수 분포와 1차 선발 유닛에서 2차 관계를 따라 취약 동작에 도달할 수 있는지는 검증 대상이다. Jev 점수는 버그 확률이나 finding 근거로 표시하지 않는다.

2026-09-24에 [C·C++·Rust·Go·Python의 여섯 프로젝트로 확장한 1차 채점](../../experiments/first-pass/README.md)에서도 **첫 A 기준선의 `0.60`은 유지**하기로 했다. 입력 형식을 함수 코드만으로 통일한 결과, 통과율은 TinyXML2 13.7%부터 7-Zip 62.5%까지 달랐다. `tar`의 `unpack_dir`(0.51)와 `go-jose`의 `decompress`(0.59)는 직접 통과하지 않았지만, 관계를 확인할 만한 호출자 또는 관련 함수는 통과했다. 따라서 이 확장 결과만으로 언어별 임계값을 새로 정하지 않는다. 이는 `0.60`의 최적성이나 알려지지 않은 결함의 도달을 입증한 결정이 아니다. A 실행에서는 프로젝트별 2차 처리량과 관계를 통한 실제 도달을 기록하고, 입력 표현·모델·질문이 바뀌면 기준을 재검토한다.
