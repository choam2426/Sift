# 2차 점수는 관련 코드 묶음 전체에 부여한다

> 재검토 상태: 2026-09-25 현재 아래 **직접 호출 1홉 묶음 경계**는 [CodeQL 데이터베이스 기반 대안](../../experiments/archive/second-pass/codeql-evidence-proposal.md)과 비교 중이며 채점에 사용하도록 확정하지 않았다. 1차 결과를 새 2차 후보의 소스로 쓰고 후보 전체를 평가한다는 결정은 유지한다.

2026-09-25 현재 1차 통과 함수는 2차 후보를 만드는 **소스**이고, 2차 Jev 점수는 새로 구성한 함수·관계 묶음 **전체**에 부여한다. 여러 함수에 걸친 동작을 평가하려는 목적에 맞추기 위해서다. 점수가 답할 구체적인 질문은 [검토 중인 입출력 제안](../../experiments/archive/second-pass/io-v1.md)에서 정한다. 첫 A 기준선에서는 각 1차 통과 함수와 원본 근거가 확인된 직접 호출 관계로 한 단계 연결된 **모든 함수**를 묶는다. 같은 스냅샷에서 함수 코드와 관계 근거가 동일한 묶음은 한 후보로 합쳐 한 번만 평가하고, 겹치지만 구성이 다른 묶음은 별도 후보로 둔다. 연결 성분 전체는 지나치게 커질 수 있어 묶음 경계로 사용하지 않는다. 크기를 이유로 함수를 제외하거나 본문을 자르지 않으며, 입력 크기는 생성 후 기록하고 실제 모델이 거부한 요청은 미평가로 보고한다. [이전의 `target` 중심 입력](../../experiments/archive/second-pass/input-v1.md)은 채점에 사용하지 않는다.
