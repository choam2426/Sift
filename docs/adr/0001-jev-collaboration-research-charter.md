# ADR 0001: Jev 협업 취약점 발견 연구의 헌장

- 날짜: 2026-10-16
- 상태: 채택. 2026-10-19부터 활성 실험 범위는 [ADR 0006](0006-logic-bug-ranker-experiment.md)으로 이동했다. 이 ADR의 C/C++ 메모리 안전성 범위는 파일럿·대조 자료로 보존한다. 2026-11-08 연구 종료: 최종 결론은 [ADR 0009](0009-conclude-research-after-stage-0.md).

## 맥락

Sift는 Jev(SystemOne)와 강한 코딩 에이전트의 협업으로 실제 취약점 발견의 시간·비용 대비 성과를 높일 수 있는지 연구한다. **도구가 목표이고 논문은 검증 수단이다.** 검증된 방법을 구현한 도구와 그 효과를 검증하는 논문을 만든다. 도구의 배포 형태와 사용자 인터페이스는 나중에 정한다.

"싸게 많이 평가하면 좋다"를 사실로 가정하지 않는다. Jev를 쓰면 왜 더 나아지는지는 반증 가능한 가설로 두고 실험으로 확인한다.

## 결정

1. **연구 질문.** 같은 금전 비용 상한에서, Jev와 협업하는 agent harness는 강한 에이전트 단독 또는 같은 예산의 동종 강한 에이전트 복수 실행보다 독립 검증된 취약점을 더 효율적으로 찾는가. 개선은 가설이며, Jev가 맡을 판단과 협업 방법은 미정이다.
2. **첫 범위.** C/C++ 오픈소스의 메모리 안전성에 대한 white-box 조사. 에이전트에는 고정된 소스와 빌드·테스트 환경을 주되 취약점 설명과 위치는 주지 않는다. 다른 언어·유형까지 일반화하지 않는다.
3. **세 비교 조건.** 강한 에이전트 하나, 총예산을 나눈 동종 강한 에이전트 복수 실행, 강한 에이전트와 Jev의 협업. 모든 조건에 같은 금전 비용 상한과 같은 대상·도구·네트워크 경계를 적용한다. 실행 시간은 상한이 아니라 기록 항목이다. 구축·모델 호출·도구 실행·재현·검증 비용과 시간도 기록한다.
4. **실행 경계.** 실행 중 일반 인터넷은 차단하고 필요한 의존성을 미리 준비한다. 모델 통신만 허용한다. 에이전트는 외부 신고나 공개를 수행하지 않는다.
5. **성공 기준.** 완료한 발견은 위치·발생 조건·근본 원인·보안 영향을 설명하는 보고서에 더해, 같은 PoC가 취약판에서 재현되고 수정판에서 기대한 이유로 실패함을 독립 검증으로 확인한 경우다. 수정판이 아직 없는 신규 결함은 확인 대기 상태로 둔다. 후보·순위·코드 비율 recall은 진단 지표이고, CVE·패치·권고는 외부 후속 성과이지 주 성공 기준이 아니다.
6. **평가 두 층.** 공개된 과거 사례로 방법과 하네스를 개발하고 고정 조건에서 반복 비교하는 통제 평가. 공개 결함은 모델의 학습 데이터에 포함됐을 수 있으므로 신규 발견 근거로 쓰지 않는다. 신규 발견 주장은 방법·모델·예산·평가기를 먼저 고정한 전향적 평가에서만 한다. 대형 앵커 프로젝트 하나와 서로 다른 공격 표면의 2~4개 프로젝트를 사전 선정 기준과 고정 커밋으로 정하고, 각 프로젝트의 같은 커밋에 세 조건을 독립 실행하며 조사 상태와 발견은 조건 간 공유하지 않는다. 비교는 프로젝트 안에서 하고 프로젝트 간 결과는 방향과 한계를 종합한다. 반복 횟수는 개발 파일럿의 비용·변동성을 본 뒤 본 평가 전에 고정한다.
7. **책임 있는 공개.** 로컬 복사본과 격리된 서비스만 조사한다. 연구자가 공식 비공개 채널로 유지관리자에게 신고하고 패치·공개 일정을 조율한다. 공개 전에는 PoC 세부 내용을 저장소·논문에 내지 않고 embargo 상태를 구분한다. 유지관리자 확인과 CVE 발급 여부도 각각 기록한다.
8. **첫 개발 실험의 강한 에이전트.** Claude Code와 Mythos 5.1(모델 식별자 `claude-mythos-5-1`). 2026-10-16 기준 이 모델로 Claude Code 세션을 실행할 수 있음을 확인했다. 통제 평가에서는 강한 에이전트 두 계열로 모델 종속성을 살피고, 전향적 평가에서는 개발 결과를 보고 한 계열을 미리 고정한다.

## 채택 당시 정하지 않은 것

종료 시점에 이 중 Jev의 역할(후보 순위기)과 비교 설계(2-arm)는 정해졌다. 나머지는 정하지 않고 연구를 마쳤다([ADR 0009](0009-conclude-research-after-stage-0.md)).

Jev의 구체적 역할과 질문, agent harness가 자율성과 구조를 어떻게 균형 잡을지, 적응적 분업 방법, 작업·상태 기록의 형태, 최종 도구의 인터페이스·배포 방식, 정확한 평가 표본과 오라클, 전향적 대상의 이름·커밋. 자율성을 막는 고정 파이프라인도, 모델이 모든 결정을 맡는 자유 실행도 미리 채택하지 않는다. 특정 선별 파이프라인이나 이벤트 그래프 같은 구현을 미리 필수로 두지 않는다.

## 재검토 조건

첫 개발 실험들의 결과로 Jev의 역할을 정할 때, 두 번째 강한 에이전트 계열을 도입할 때, 전향적 평가를 설계할 때.
