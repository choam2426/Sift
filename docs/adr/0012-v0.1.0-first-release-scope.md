# v0.1.0은 사내 연구원이 오픈소스 C/C++ 코드베이스에 쓰는 첫 배포다

2026-09-27 결정. v0.1.0은 실험 이정표가 아니라 **첫 배포 시점**이다. 목표는 연구원이 C/C++ 소스 코드베이스를 CLI로 지정하면, [첫 프로파일](0011-vulnerability-type-profiles.md)(외부 입력에서 유도된 값의 경계·정수 오류)에 대해 근거 있는 후보 목록과 조사 범위 보고를 받고, 그 후보를 직접 검토해 버그를 확인할 수 있는 것이다.

## 첫 사용자와 대상

- 첫 사용자는 사내 취약점 연구원이다. 외부 배포를 위한 설치·문서·안전장치는 이 버전의 범위가 아니다.
- 대상은 **오픈소스 C/C++ 소스 코드베이스**다. 바이너리·디컴파일 코드는 제품 목적에 포함되지만 첫 배포에서는 제외하고, 코드 조회 도구의 인터페이스는 소스와 디컴파일 결과에 같게 설계해 이후 버전에서 붙인다. 오픈소스 대상은 [CodeQL 사용 조건](0006-codeql-source-relation-experiment.md)의 공개 소스 범위와도 맞는다.
- 대상 규모의 기준(함수 수 또는 코드 줄 수)과 그에 따른 비용 상한은 구현하면서 정한다. 2026-09-27 현재 미결이다.

## 사용자가 받는 것

- **finding 보고:** 근거 있는 후보마다 위치, 입력 출처, 유도 경로, 검사 위치와 조건, 사용 범위, 위반 조건, 다음 검증 방법. 보고서만 보고 코드로 바로 갈 수 있어야 한다.
- **조사 범위 보고:** 평가한 함수 수, 조사한 후보 수, 기각 목록, 미평가·미조사와 이유.
- **진행 중 확인과 재개.**
- **비용 예측과 상한:** 실행 전 예상 호출 수·비용을 보여주고 상한을 지정한다. 외부 모델에 코드를 보내는 것과 크레딧 소진은 사용자가 통제한다.

## 범위

| 포함 | 제외 |
|---|---|
| C/C++ 소스, CLI | 바이너리·디컴파일, GUI, 다른 언어 |
| 1차 전수 선별 → 3차 정적 검증 | 동적 검증 |
| 첫 프로파일 | 둘째 이후 프로파일 |
| 2차: 배포 전 실험으로 판정해 [1차 순위 기준선](0010-three-stage-structure.md)을 이기면 포함, 아니면 제외 | — |
| 설치·설정 문서, 알려진 한계 문서 | 외부 배포용 패키징 |

동적 검증이 없으므로 이 버전의 finding에 확인된 버그는 없다. 결과 분류는 [제품 명세](../product.md#결과)를 따른다.

## 배포 기준

1. **실사용 검증:** 라벨 사례가 아닌 실제 오픈소스 대상에 사내 연구원이 직접 돌리고 후보를 검토해, 근거 있는 후보의 대부분이 검토할 가치가 있었다고 판단한다. 수치 기준은 첫 실사용 후 정한다.
2. **라벨 사례 도달:** 첫 프로파일의 알려진 버그 사례 5개 이상(서로 다른 프로젝트, 수정 커밋 있음)에서 알려진 버그가 근거 있는 후보로 나온다. 필요한 개수는 배포 전 측정값을 보고 정하되 0개면 배포하지 않는다.
3. **거짓 후보 부담:** 연구원이 후보 하나를 기각하는 데 드는 시간이 감당할 수준이다. 1번의 실사용에서 잰다.
4. **비용:** 정한 규모의 대상을 정해진 상한 안에서 완주한다.
5. **한계 명시:** 선별이 구조적으로 보지 못하는 유형, 미해결 호출, 언어 범위를 문서와 보고에 적는다.

## 배포 전 내부 이정표

1. 평가 하네스와 라벨 사례 확보.
2. 3차 최소 구현(코드 조회 도구, 예산, finding 요건 강제).
3. 1차 → 3차 종단 완주.
4. 2차 실험과 채택 판정.
5. 실사용 검토와 보고 형식 다듬기.

이 순서는 2차의 채택 조건이 3차 예산에서의 비교이므로 3차와 평가 사례가 먼저 필요하다는 판단에서 나왔다. 구현 중 바뀌면 이 문서에 날짜와 함께 남긴다.
