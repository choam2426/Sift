# 평가 사례는 수동 선정 CVE와 ARVO를 섞어 설계용과 봉인용으로 나눈다

2026-09-27 결정. [v0.1.0 배포 기준](0012-v0.1.0-first-release-scope.md)의 라벨 사례는 **설계·튜닝용 5개와 봉인용 3개**로 나눈다. 설계용은 NVD에서 수동 선정한 CVE, 봉인용은 ARVO(OSS-Fuzz 재현 데이터셋)에서 고른다.

## 선정 기준

1. [첫 프로파일](0011-vulnerability-type-profiles.md)에 해당한다. CWE-119/125/787/190/191 계열을 1차 필터로 쓴다.
2. C/C++, OSI 라이선스, CodeQL 데이터베이스를 만들 수 있는 규모다.
3. 취약 리비전과 수정 커밋이 명확하고, 수정 커밋이 실제 원인을 고쳤는지 확인했다.
4. 모델 기억 위험을 감안한다. 유명 CVE는 LLM이 코드를 읽지 않고도 맞힐 수 있으므로 최근 것이나 덜 알려진 것을 섞고, 유명 사례의 결과는 그 위험을 적어 해석한다.
5. 입력 형식이 다양하다(압축, 이미지, XML, 네트워크 프로토콜).

## 왜 섞는가

- **설계용은 수동 CVE:** 파급력이 보장되고 사례 선택의 이유를 남길 수 있다. OSS-Fuzz 발견 버그는 ASAN 크래시 기준이라 파급력이 낮은 over-read가 많고, 퍼저가 잘 찾는 버그에 도구를 맞출 위험이 있다.
- **봉인용은 ARVO:** 봉인 사례는 파급력보다 설계 중 보지 않았다는 독립성이 중요하고, ARVO는 취약 커밋·수정 커밋·재현 입력이 갖춰진 사례가 많아 고르기 쉽다. 재현 입력은 이후 동적 검증에도 쓸 수 있다.
- Magma는 유명 CVE를 이식한 코드라 첫 라벨에는 쓰지 않고 동적 검증을 붙일 때 다시 본다.

## 사례 구성 — 제안

설계용: 7-Zip 26.01(기존 라벨), zlib, libexpat, libtiff, stb_image 또는 cJSON. 봉인용: libarchive, lwIP 또는 FreeRDP, curl. 각 사례의 리비전·수정 커밋·필수 줄·기전은 확인 후 `experiments/labels/`에 고정하며, 확인 전까지 이 목록은 제안이다.

## 규칙

- 봉인 사례는 배포 기준 판정에만 쓰고 설계 중 열어보지 않는다. 열어봤으면 다른 사례로 다시 봉인한다.
- 비버그 대조군은 각 사례의 **수정 커밋 이후 리비전**을 그대로 쓴다. 같은 코드에 검사만 더해진 상태라 거짓 후보 측정에 가장 정직하고 라벨링 비용이 없다.
- 라벨은 모델에 보이지 않는 채점 자료로만 쓴다.
