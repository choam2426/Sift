# Sift 제품 명세

## 목적과 사용자

Sift는 취약점 연구원의 에이전트가 큰 코드베이스에서 **Jev로 효율적으로 우선순위를 정하게 하는** 스킬과 스크립트다. 전수 선별과 탐색 중 재선별로 에이전트의 조사 예산을 유망한 코드에 쓰게 하고, 무엇을 평가하고 조사하고 기각했는지 기록한다.

사용자는 취약점 연구원이며, 연구원은 자신이 쓰는 에이전트(Claude Code, Codex 등)에 Sift를 붙여 함께 분석한다. 심층 분석, 검증, PoC와 판정 기준은 연구원과 에이전트의 일이다. Sift는 판정을 요구하지 않고 기록한다. 2026-09-27 이전의 명세는 Sift가 분석 전체와 최종 보고서를 맡는 도구였다. 방향 전환의 이유는 [ADR 0015](adr/0015-agent-harness-direction.md)에 있다.

## 분석 대상

- 소스 코드베이스.
- 바이너리. 에이전트가 Ghidra 등으로 디컴파일한 결과를 Sift에 넣는다. IDA Pro는 선택 가능한 도구로 고려한다.
- 연구원이 이미 디컴파일한 결과.

Sift는 주어진 대상의 모든 분석 유닛을 평가하고, 평가하지 못한 부분을 결과에 명시한다.

## Sift가 하는 일

| 일 | 내용 | Jev |
|---|---|---|
| 전수 선별 | 대상의 모든 함수를 평가해 조사 순서를 만든다 ([ADR 0004](adr/0004-first-pass-function-triage.md)) | 실행 전 |
| 탐색 중 재선별 | 에이전트가 넘긴 함수 집합(피호출자, 파일, 변경분 등)의 순서를 즉시 정한다 | 탐색 루프 안 |
| 범위 기록 | 평가한 것, 배부한 것, 에이전트가 기록한 판정, 미평가·미조사를 실행 디렉터리에 남기고 보고한다 | 없음 |

Jev 점수는 우선순위 신호이며 버그 확률로 표시하지 않는다. 조사·판정·검증은 에이전트가 하고, Sift는 그 결과를 받아 적는다. 판정 파일은 사람과 에이전트가 함께 쓸 수 있도록 추가 전용으로 둔다.

## 사용 경험

에이전트용 스킬과 그 안의 스크립트로 제공한다. 연구원이 직접 스크립트를 써도 된다. 실행은 실행 디렉터리의 상태로 이어갈 수 있다. GUI, 무개입 전체 분석, Sift 자체의 PoC 실행은 범위 밖이다. 외부 모델에 코드를 전달할지와 Jev 비용은 사용자가 통제한다.

## 결과

Sift가 내는 것은 우선순위와 범위 보고다. 결과 분류는 에이전트가 기록한 판정으로 채운다.

| 분류 | 조건 | 출처 |
|---|---|---|
| 확인된 버그 | 에이전트가 재현을 기록했다 | 판정 기록 |
| 근거 있는 후보 | 에이전트가 근거와 함께 후보로 기록했다 | 판정 기록 |
| 기각 | 에이전트가 이유와 함께 기각했다 | 판정 기록 |
| 배부됐으나 판정 없음 | 우선순위로 넘겼지만 기록이 없다 | Sift |
| 미평가·미조사 | 한도 초과, 오류, 예산 부족 | Sift |

## 성공 지표

- 주 지표: 알려진 버그 사례에서, Sift를 쓴 에이전트가 쓰지 않은 에이전트보다 같은 예산에서 근거 있는 후보에 더 많이 도달하는가.
- 보조 지표: Jev 비용, 에이전트 예산 절감량, 미평가·미조사 비율.
- 중단 조건: 위 비교에서 분명한 차이가 없으면 우선순위 기능을 접고 범위 기록만 남긴다.

## 미결 사항

- 에이전트 비교 실험의 예산 단위(토큰, 턴, 시간)와 반복 횟수.
- 탐색 중 재선별의 입력 형태.
- 함수 추출과 관계 조회 도구 ([ADR 0014](adr/0014-python-asyncio-and-code-lookup.md) 재검토 중).
