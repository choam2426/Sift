# 2차 분석 구조 비교 실험

이 실험은 **전 유닛 Jev 평가 → 관련 코드와 함께 재선별 → LLM 심층 분석** 흐름에서 2차 분석 방식을 고른다. [1차 Jev 입력 범위 실험](../first-pass/README.md)에서 입력 방식과 통과 기준을 먼저 고정한다. Jev 점수는 조사 대상을 고르는 신호이며, 최종 finding에는 별도의 코드 근거와 검증이 필요하다. 아래 구조는 합의 전의 비교 대상이다.

## 후보

| 방식 | 관련 코드 선택 | 2차 판단 | 3차 |
|---|---|---|---|
| A | 호출·참조·공유 상태 등 추출된 관계를 규칙으로 묶음 | Jev | 심층 LLM |
| B | 가벼운 LLM이 관계 후보에서 관련 코드를 고름 | Jev | 심층 LLM |
| C | 가벼운 LLM이 관련 코드를 고르고 심층 분석 대상 여부도 판단 | 가벼운 LLM | 심층 LLM |
| 기준선 | 별도 2차 선별 없음 | 없음 | 심층 LLM이 필요한 코드를 조회 |

B에서는 가벼운 LLM이 코드를 고르고 Jev가 판단한다. C에서는 가벼운 LLM이 두 판단을 맡는다. 2차가 도움이 되지 않는지도 기준선으로 확인한다.

## 공통 입력과 통제

- **단위:** 함수 하나를 1차 Jev 평가 유닛으로 사용한다. 관련 함수 묶음은 그 유닛의 판단 맥락이며, 별도의 버그로 세지 않는다.
- **단계 경계:** [1차 기본안](../../docs/adr/0004-first-pass-function-triage.md)은 대상 함수 전체 본문만 평가한다. 다른 함수 본문이나 함수 간 관계를 따라 모은 코드는 2차 입력에만 넣는다. 클래스·모듈 선언 추가는 [1차 실험](../first-pass/declarations/README.md)에서 순위를 개선하지 못해 기본안에 넣지 않았다.
- **공통 입력:** 동일한 함수 목록, 1차 Jev 응답, 원본 코드, 함수 간 관계 후보를 사용한다. 관계 후보에는 호출·참조·공유 상태의 출처와 위치를 붙인다. 모델이 고른 참조는 실제 코드와 대조한다.
- **입력 한도:** A·B·C에 같은 관계 후보 목록과 2차 판단 맥락의 최대 크기를 준다. 넘치는 경우 공통 규칙으로 자르고, 잘린 내용을 기록한다.
- **고정 조건:** 대상 리비전, 추출 결과, 관계 후보, 1차 Jev 응답, 모델 버전·질문·설정과 실행 순서를 한 실행 단위로 고정한다. 정답 라벨, 패치 차이와 버전 표지는 모델 입력에서 제외한다. 수정 버전은 별도 비버그 입력으로만 사용한다.

## 실행 순서

1. **작동 확인:** 로컬 7-Zip 취약 버전과 수정 버전의 기존 함수·Jev 산출물을 재사용한다. 알려진 오류 기전의 관련 함수와 필수 맥락을 라벨로 작성한다. 이 사례만으로 구조를 채택하지 않는다.
2. **2차만 비교:** 같은 1차 통과 유닛을 A·B·C에 넣는다. 각 방식은 3차로 보낼 유닛의 순서, 선택한 코드와 판단 응답을 남긴다. 맥락 누락, 버그 유닛 탈락, 비버그 통과량, 호출 비용·시간을 확인한다. 기준선은 1차 Jev 순서를 사용한다.
3. **작은 종단 비교:** 각 방식의 출력에 동일한 심층 LLM과 코드 조회 도구를 적용한다. 동일한 3차 호출·토큰 예산에서 실제 버그가 근거 있는 finding으로 이어지는지 확인한다. 전체 모델 비용·시간도 따로 비교한다.
4. **별도 사례 확인:** 소스 코드와 디컴파일된 코드에서 버그 사례와 유사한 비버그 사례를 각각 포함한다. 작동 확인 사례로 질문과 기준을 조정한 뒤에는 별도 사례의 결과를 보고 바꾸지 않는다.

## 기록과 판정

각 실행은 입력 스냅샷 식별자, 방식, 유닛 ID, 선택한 관련 코드의 ID·위치, 2차 응답, 3차 처리 순서, 모델·프롬프트 버전, 토큰·비용·시간, 실패·재시도 내역을 남긴다. 산출물은 Git에서 제외한 `experiments/second-pass/runs/<run-id>/`에 보관한다. 라벨은 모델에 전달하지 않는 별도 파일에 둔다.

버그별로 **1차 직접 선발 → 1차 선발 유닛에서 허용된 관계로 도달 가능 → 2차 통과 → 3차 도달 → 근거 있는 finding**을 구분해 추적한다. 목표 함수 자체의 1차 점수가 낮아도 다른 선발 유닛의 관련 코드로 들어올 수 있다. 어느 선발 유닛에서도 허용된 관계·입력 한도 안에 닿지 않는 버그는 1차 선별과 관계 추출의 한계로 별도 보고한다. 닿을 수 있었지만 2차 방식이 버린 경우는 그 방식의 탈락으로 기록한다. 유닛 수뿐 아니라 서로 다른 버그 기전 수로도 도달률을 계산한다. 맥락 포함률, 비버그 통과량, 전체 비용·시간을 함께 보고한다. 소스와 디컴파일 결과는 분리한다.

1차 통과 기준은 [첫 구현값 `Noul ≥ 0.60`](../../docs/adr/0004-first-pass-function-triage.md)을 사용한다. 2차 실험 실행 전에는 공통 맥락 한도, 3차 예산, 반복 횟수, 채택 기준을 정한다. **버그 도달률과 근거 있는 finding의 보존을 우선**하고, 그 조건을 만족하는 방식끼리 비용·시간을 비교한다. 수치와 라벨 사례는 실험 준비 시 합의해 고정한다. 실험 결과와 채택 이유는 `../../docs/adr/`에 기록한다.
