# A의 직접 호출 입력 사전 점검

> 상태: 2026-09-25 **Jev 호출 전 사전 점검 완료, 채점에는 사용하지 않음**. 7-Zip 26.01의 기존 1차 범위와 CodeQL 2.27.1 결과에 한정한다. 아래 `target` 중심 구조와 28,000바이트 선택 규칙은 [ADR 0007](../../docs/adr/0007-second-pass-scores-related-code-group.md)에서 변경됐다. 현재의 [크기 제한 없는 묶음 사전 점검](direct-call-group-dry-run.md)을 2차 입력 준비에 사용한다. 이 기록은 이전 관계·코드 도달 점검의 경과로 보존한다.

## 고정 입력과 생성 규칙

- 1차의 `code-only-v1`로 평가한 C 파일 55개, 함수 602개와 `Noul ≥ 0.60`을 통과한 **376개 앵커**를 사용했다. 함수·점수 파일과 원본 소스의 해시·리비전을 생성기에서 검증한다. 이 범위 밖 C 파일 18개는 포함하지 않는다. [1차 실험](../first-pass/README.md)
- [ADR 0006](../../docs/adr/0006-codeql-source-relation-experiment.md)에 따라 CodeQL CLI 2.27.1로 55개 파일을 모두 컴파일해 데이터베이스를 만들었다. [`build_7zip_scope.py`](codeql-pilot/build_7zip_scope.py)는 1차 목록에 있는 파일만 Clang으로 컴파일한다. [`source_functions.ql`](codeql-pilot/cpp/source_functions.ql), [`source_call_edges.ql`](codeql-pilot/cpp/source_call_edges.ql), [`unresolved_source_calls.ql`](codeql-pilot/cpp/unresolved_source_calls.ql)의 CSV가 원시 관계 자료다. DB·CSV·생성 상태는 Git 제외된 `runs/codeql-a-direct-2026-09-25/`에 있다.
- [`dry_run_direct.py`](dry_run_direct.py)는 CodeQL의 함수 파일·이름·정의 위치가 1차 함수의 소스 범위에 들어갈 때만 ID를 연결한다. 호출 위치가 호출자 본문 안에 있고 **원본 호출 줄에 대상 이름이 보이는** 간선만 `direct_call`로 인정한다. 이 기준에 맞지 않는 CodeQL 결과와 미해결 호출은 모델 입력에서 제외하고 실행 기록에 남긴다. 같은 이름의 다른 함수, 조건부 컴파일 분기, 매크로 확장 호출을 근거 없이 연결하지 않기 위한 보수적 규칙이다. [C/C++ `getTarget()` 의미](https://codeql.github.com/codeql-standard-libraries/cpp/semmle/code/cpp/exprs/Call.qll/predicate.Call%24FunctionCall%24getTarget.0.html)
- 각 앵커에서 직접 피호출자, 그다음 직접 호출자를 함수 ID순으로 검토한다. 완전한 함수 코드와 모든 직접 호출 근거를 함께 넣었을 때 `state`가 **28,000 UTF-8바이트 이하**인 후보만 선택한다. 큰 후보는 건너뛰고 다음 후보를 검토한다. 앵커 코드는 자르지 않는다. JSON은 [입력 형식 제안](input-v1.md)의 `target`·`related_functions`·`relations` 순서로 공백 없이 직렬화한다. 이 선택 순서와 바이트 목표는 채점 전 검토할 값이다.

## 결과

| 항목 | 결과 |
|---|---:|
| 1차 통과 앵커에서 만든 입력 | 376/376 |
| CodeQL 정의를 1차 함수와 연결 | 589/602 |
| 정의를 연결한 통과 앵커 | 371/376 |
| 허용한 직접 호출 함수 쌍 / 호출 위치 근거 | 643쌍 / 774곳 |
| 관련 함수가 하나 이상 들어간 앵커 | 297/376 |
| 관련 함수가 없는 앵커 | 79/376 |
| 28KB 목표로 후보 일부를 뺀 앵커 | 8/376 |
| 앵커 코드만으로 28KB를 넘은 입력 | 0 |
| 대상 미해결 호출이 있는 앵커 | 110/376 |

`state` 크기는 중앙값 4,220바이트, 90백분위 17,488바이트, 최대 27,841바이트였다. 관련 함수 수는 중앙값 2개, 최대 17개다. CodeQL 질의의 호출 간선 1,208행 중 176행은 대상 정의가 1차 범위·빌드 변형에 연결되지 않았고, 202행은 호출자 정의가 연결되지 않았으며, 56행은 호출 줄에 대상 이름이 없었다. 함수 정의가 연결되지 않은 13개에는 조건부 컴파일 분기의 다른 구현이 포함된다. **이들을 관계가 없다고 판정하지 않는다.** 원시 질의에서 대상 미해결인 호출 위치 267곳도 별도로 보관했다. 자세한 수치와 각 입력 해시는 로컬 `dryrun-direct-v1/summary.json`, `manifest.json`, `records.jsonl`에 있다.

[CVE-2026-14266 라벨](labels/cve-2026-14266.json)은 모든 입력을 만든 **뒤에만** 도달 여부 확인에 사용했다. `XzUnpacker_Code`는 1차 순위 3위(0.86)였고, 생성 입력은 27,539바이트에 관련 함수 15개를 포함했다. 이 입력에는 라벨에 적힌 필수 소스 줄 6곳이 모두 **함수 전체 코드**로 포함됐다. 반면 버그 지점 `MixCoder_Code` 자체를 앵커로 한 입력은 15,282바이트이고, `XzDecMix_Init`의 931행은 들어가지 않았다. 이는 한 단계 직접 호출만으로는 앵커별 맥락이 달라진다는 관찰이다. 소스 줄이 입력에 있다는 사실만으로 Jev가 버그를 식별하거나 3차 분석이 재현할 것이라고 주장하지 않는다. 라벨 점검은 `dryrun-direct-v1/label_audit.json`에 분리했다.

## 남은 판정

이번 이전 사전 점검은 [당시 입력 형식](input-v1.md)을 실제 376개 상태로 만들 수 있고, 알려진 7-Zip 버그의 필수 코드 줄이 **적어도 한 앵커**에 도달한다는 것을 확인했다. 동시에 79개 앵커의 관계 맥락 부재와 조건부 컴파일·매크로·함수 포인터 누락을 드러냈다. 크기를 이유로 함수를 제외하는 규칙은 현재의 2차 후보 생성에 적용하지 않는다. 모든 언어와 디컴파일 결과에서 같은 품질의 그래프를 얻었다는 결론은 아니다.
