# 직접 호출 기반 2차 묶음 입력 사전 점검

> 상태: 2026-09-25 **Jev 호출 전 사전 점검 완료**. 7-Zip 26.01의 지정된 C 파일 55개, 1차 `code-only-v1` 결과와 CodeQL CLI 2.27.1에 한정한다. 대상 리비전·함수 추출·CodeQL 질의 또는 관계 판정이 바뀌면 다시 생성한다.

## 생성 규칙

[`dry_run_groups.py`](dry_run_groups.py)는 1차에서 `Noul ≥ 0.60`을 받은 함수 376개 각각을 출발점으로 사용한다. [기존 직접 호출 사전 점검](direct-call-dry-run.md)과 같은 원본 대조 규칙으로 인정한 직접 호출 관계에서, 출발 함수의 호출자와 피호출자를 **모두** 포함한다. 묶음에 포함된 함수들 사이의 다른 확인된 직접 호출 관계도 모두 넣는다. 함수 본문과 호출 근거를 크기로 선택·제외·절단하지 않는다.

모델에 보낼 `state`는 [묶음 평가 입출력 설계](io-v1.md)의 `functions`와 `relations` 구조로 만들되, 출발 함수를 평가 대상으로 표시하지 않는다. 함수와 관계를 정규화한 상태가 같으면 한 묶음으로 합치고 모든 출발 함수 ID를 실행 기록에 연결한다. 자기 자신을 호출하는 관계는 기록하되 이웃 함수를 하나 더 늘린 것으로 세지 않는다. 묶음 ID에는 소스 리비전과 실제 `state` 바이트를 함께 해시한다. 원본 1차 점수·소스 리비전·라벨은 모델 입력에 넣지 않는다. 결과는 Git 제외된 `runs/codeql-a-direct-2026-09-25/dryrun-groups-unbounded-v2/`에 보관했다. `manifest.json`에 입력 해시와 규칙을, `states.jsonl`·`groups.jsonl`·`origins.jsonl`에 상태와 출발 함수 대응을 기록했다.

크기는 **관측값**이며 후보 생성이나 중복 제거에 사용하지 않았다. 기존 [크기 기반 입력](direct-call-dry-run.md)의 28,000바이트 규칙 때문에 빠졌던 함수도 새 입력에는 포함된다. 실제 Jev 요청이 입력 한도를 거부하는지는 아직 확인하지 않았다. 거부가 발생하면 해당 후보를 미평가로 기록해야 한다.

[CVE-2026-14266 라벨](../../labels/cve-2026-14266.json)은 모든 입력을 만든 뒤 도달 여부 확인에만 사용했다. `XzUnpacker_Code`에서 시작한 묶음은 함수 21개·51,287바이트이며 라벨의 필수 소스 위치 6곳이 **모두 원본 함수 코드 안**에 있다. 이는 필요한 코드가 입력에 도달했다는 뜻이며, Jev의 2차 점수나 버그 검출 결과는 아니다. 상세 결과는 로컬 `label_audit.json`에 분리했다.

함수 정의 매핑 589/602, 허용된 직접 호출 함수 쌍 643개와 호출 위치 근거 774곳, 미해결 호출 위치 267곳은 기존과 같다. 조건부 컴파일과 함수 포인터 등의 누락은 여전히 남는다. 그래프 연결 성분 전체를 묶지 않았으며 한 출발 함수에서 직접 연결된 이웃까지만 포함했다.
