# CodeQL 데이터베이스 기반 2차 입력 제안

> 상태: 2026-09-25 **동작 경계·입출력은 논의용 제안; 미합의·미실행**. CodeQL DB와 Jev의 역할 분담은 [ADR 0008](../../docs/adr/0008-codeql-db-facts-jev-vulnerability-judgment.md)에 기록했다. 기존 [직접 호출 1홉 입출력안](io-v1.md)을 대체할 구조를 검토한다. 크기를 이유로 코드나 근거를 제외하지 않는다.

## 역할 분담

CodeQL 데이터베이스는 고정된 소스 스냅샷에서 추출한 코드 구조와 의미 관계를 조회하는 기반이다. 공식 [데이터베이스 설명](https://codeql.github.com/docs/codeql-overview/about-codeql/)에 따르면 추상 구문 트리, 타입·이름 결합, 데이터 흐름과 제어 흐름을 질의할 수 있다. Sift는 **취약점 탐지 규칙·기본 보안 질의·경고 순위를 사용하지 않고**, 언어별 중립적인 질의로 2차 입력에 필요한 코드 사실을 꺼낸다. DB에 추출된 구문·타입·위치 사실과 [QL 라이브러리가 계산한 데이터 흐름](https://codeql.github.com/docs/codeql-language-guides/analyzing-data-flow-in-cpp/)을 구분한다. 후자는 모델·설정에 따른 가능한 관계이며 실제 실행 경로나 취약성을 증명하지 않는다. **Jev가 후보 동작에 실제 보안 취약점이 있는지를 판단**한다. 3차는 그 판단의 오류 기전과 방어 검사, 재현 가능성을 확인한다.

## 1차 결과에서 2차 후보까지

1. 1차 통과 함수를 **출발점**으로 고정한다. 취약점 이름·라벨·패치·1차 점수는 CodeQL 질의의 선별 조건이나 Jev 입력으로 쓰지 않는다.
2. CodeQL 데이터베이스에서 출발 함수와 관련된 **구조·의미 사실**을 조회한다. 함수·호출 위치, 인자와 반환값의 전달, 값의 정의·사용, 객체·필드의 읽기·쓰기, 분기와 조건 검사, 타입과 원본 위치를 후보 사실로 둔다. 각 관계는 `db_extracted` 또는 `ql_derived`로 구분하고, 계산에 쓴 질의·모델·설정과 확인 범위를 기록한다. 같은 필드 선언을 참조한다는 사실만으로 같은 객체의 상태 흐름이라고 표시하지 않는다.
3. 이 사실을 연결해 **하나의 동작을 설명하는 코드 단위**를 2차 후보로 만든다. 함수 수나 호출 홉 수를 미리 정하지 않는다. 후보에 속한 함수는 전체 본문을 넣고, 값·상태·제어 관계의 근거 위치와 관련 선언을 함께 보낸다. 출발 함수가 여럿이어도 같은 코드와 관계로 같은 후보가 생기면 한 번만 평가한다. 서로 다른 근거·동작이면 함수 집합이 같아도 별도 후보다.
4. 관계를 해석하지 못한 부분과 데이터베이스의 빌드·언어 범위는 명시한다. 질의 결과가 없다는 사실은 안전 판정이나 0점이 아니다. 실제 API가 입력을 거부하면 축소하지 않고 미평가로 남긴다.

### 동작 경계 — 첫 검증 규칙 제안

후보 하나의 경계를 **진입 맥락 + 다루는 객체·상태 + 관찰 가능한 효과**로 기술한다. 진입 맥락은 호출 위치나 초기화이며, 효과는 반환값·출력 버퍼·상태 변경·외부 호출 등 코드에 나타난 결과다. 후보에는 해당 효과에 관여하는 값들의 이동, 같은 객체의 상태 초기화·변경·사용, 효과를 제어하는 조건과 관련 호출을 함께 담는다. 포인터와 길이, 상태와 호출 횟수처럼 **한 연산·분기·상태 전이에 공동으로 쓰이는 값은 갈라놓지 않는다.** 반복 호출의 가능성을 나타내는 호출 구조는 담되 실제 반복 실행을 입증했다고 표시하지 않는다.

선택한 효과에 영향을 주지 않는 별도 객체·동작은 경계 밖에 둔다. 이 경계는 사실 관계로 확인해야 하며 무제한 연결 성분이나 임의의 호출 홉 수로 대체하지 않는다. 진입·객체 동일성·효과의 연결을 확인하지 못하면 그 의존성을 `unresolved`로 기록한다. 이 규칙 자체는 **아직 합의되지 않았고** 아래 국소 점검에서 자동 추출 가능성을 확인해야 한다.

## 입출력 계약 초안

| 산출물 | 포함할 내용 | 판정 주체 |
|---|---|---|
| `code_facts` | CodeQL 질의 버전, 엔티티 ID, 원본 위치, 관계 종류·방향·근거, `db_extracted`/`ql_derived`와 계산 설정, 미해결 사실 | CodeQL DB 조회 + 원본 대조 |
| `candidates` | 진입·객체·효과로 정의한 동작 경계, 참여 함수의 전체 코드, 값·상태·제어 관계, 지원 선언·빌드 구성·외부 계약·미확인 가정 | Sift의 후보 구성 규칙 |
| `jev_responses` | 후보 ID·질문·모델·원시 Noul·오류·사용량 | Jev의 취약성 판단 |
| `findings` | 주장한 오류 기전, 방어 검사 확인, 코드 근거와 재현 결과 | 3차 분석·검증 |

`candidate_id`는 소스 스냅샷과 정규화한 **동작 경계·관계 근거·코드**에서 만든다. `state_sha256`은 실제 Jev 요청 상태의 해시로 별도로 기록한다. 출발 함수 ID와 1차 점수는 후보와의 **다대다 대응**을 실행 기록에만 남기며, 한 후보 점수를 출발 함수별 독립 점수로 복제하지 않는다. Jev 질문은 후보 전체의 동작에 **구체적인 보안 취약점이 있는가**를 묻는다. Jev 값은 보정된 확률이나 확정된 finding이 아니며, 낮은 값도 안전성의 증명이 아니다. 보안 영향을 뒷받침할 코드가 입력에 부족하다면 그 한계를 응답 해석에 반영한다.

## 검증할 위험

- CodeQL 데이터베이스의 추출·빌드 범위와 언어별 관계 제공 범위가 다르다. 없는 사실을 관계 부재로 단정하지 않는다.
- 자료 흐름만으로 반복 호출에 걸친 상태 회계 오류를 설명할 수 있다고 가정하지 않는다. [7-Zip 사전 점검 라벨](../../../bench/labels/cve-2026-14266.json)의 `outWritten`, 길이 값, 초기화와 호출 사이의 관계가 **중립적인 사실 질의**로 얼마나 재구성되는지 확인한다. 라벨은 결과 평가에만 사용하며 질의 조건이나 입력으로 쓰지 않는다.
- Jev가 취약성 판단을 하려면 코드의 연결뿐 아니라 값의 이동과 조건 검사를 볼 수 있어야 한다. CodeQL 사실이 부족한 후보는 `unresolved`로 기록하고 그 이유를 확인한다.
