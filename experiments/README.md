# 실험 결과 요약

2026-09-27 기준. 확정된 결과만 적는다. 절차·스크립트·중간 제안은 [`archive/`](archive/)에 보존하며 새 실험은 `sift` 패키지를 사용한다. 원시 응답은 Git에서 제외된 `runs/`에 둔다. 라벨은 [`labels/`](labels/)에 있고 모델에 보이지 않는 채점 자료로만 쓴다.

## 1차 전수 선별 — 확정 (ADR 0004)

모델 `jev-1.13.0`, 입력은 함수 전체 본문만, 질문은 `Is this function worth a security researcher's time to inspect further for bugs?` 단일 Noul, 통과 기준 `Noul ≥ 0.60`.

| 실험 | 결과 | 기록 |
|---|---|---|
| 질문 비교 (Python 6개 취약점, 함수 277개, 3반복) | 상위 10% 예산에서 단순 조사 가치 질문 5/6 도달. 대조 판단 질문 3/6, 구체적 의심 3~4/6, 함수 길이 4/6 | [contrastive](archive/first-pass/contrastive/README.md) |
| 선언 추가 (같은 표본) | 클래스·모듈 선언을 붙여도 5/6로 같고 입력 토큰 33% 증가 → 채택하지 않음 | [declarations](archive/first-pass/declarations/README.md) |
| 임계값 | `0.60`이 277개 중 40~42개(14~15%) 통과, 5/6 기전 유지. `0.70`은 4/6 | [first-pass](archive/first-pass/README.md) |

## 2차 재선별 — 미확정

7-Zip 26.01 통과 함수 376개를 출발점으로 네 입력 방식(호출·값·상태·효과) × 다섯 질문 (P1~P5) 22,885건을 계획했고 HTTP 402로 18,882건에서 중단했다. 성공 응답 입력 1.1억 토큰.

| 결과 | 내용 |
|---|---|
| 후보 수 | 출발 함수 376개에서 후보 4,577개 (호출 746, 값 1,779, 상태 224, 효과 1,828). 재선별인데 대상이 12배로 늘었다 |
| 필수 코드 포함 | CVE-2026-14266 필수 줄을 한 후보에 담은 것은 호출 방식 7개, 상태 방식 1개. 값·효과 방식은 0개 |
| 질문별 순위 | 필수 코드 후보의 최고 순위는 P4 상태 전이(호출 7/597위, 상태 16/191위), P2 계약(14위, 26위), P3 검사·사용(22위, 33위). P1·P5는 100위 밖 |
| 결론 | 사례 하나뿐이라 방식·질문의 우열은 판단하지 않았다. 병목은 채점보다 후보 생성이다 |

이 결과와 ADR 0010·0011에 따라 2차는 **출발 함수당 하나의 묶음으로 재선별**하는 방향으로 바뀌었고, 채택 여부는 1차 순위 기준선과의 3차 비교로 정한다. 세부 기록: [second-pass](archive/second-pass/README.md), [부분 평가](archive/second-pass/partial-results-7zip-2026-09-27.md).

## 코드 조회: C/C++ 함수 추출 — 2026-09-27

결정과 이유는 [ADR 0014](../docs/adr/0014-python-asyncio-and-code-lookup.md)에 있다.

**tree-sitter (Clang 기준 목록과 대조).** 끝 줄 일치 기준으로 Expat 280/283, 7-Zip 26.01 `C/` 631/643. 세미콜론 없는 문장 매크로 때문에 라벨 함수 `MixCoder_Code`가 580~2877줄로 잡혔고(실제 580~785), 보정 후에도 `Bcj2Dec_Decode`와 Zstd 디코더 4개가 통째로 빠졌다.

**도구 비교 (조사 에이전트가 직접 실행).** CodeQL 7-Zip 643/643·Expat 283/283. Joern은 7-Zip 원문 일치 612/643이고 `#include`된 `.c` 35개 누락, 1000자 절단 등 조용한 누락이 있었다. ctags·srcML은 7-Zip 함수 25% 이상 누락. libclang은 7-Zip 322개 파일을 오류 없이 처리했다.

**libclang, 가능한 모든 구성 (`sift.cfamily`, 7-Zip 26.02 `C/`, 10코어).** 매크로 켜고 끄기를 어디에 적용할지 비교했다.

| 구성 | 파싱 | 시간 | 함수 |
|---|---:|---:|---:|
| 모든 비활성 줄에 | 1,357 | 98초 | 914 |
| 정의가 추정되는 비활성 줄에만 (채택) | 431 | 17~19초 | 909 |
| 같은 작업을 1개 프로세스로 | 431 | 62초 | 909 |

기준 구성만 쓰면 함수의 약 17%를 못 봤다. 채택한 방식이 놓친 5개는 tree-sitter가 정의를 찾지 못한 곳이며, 모두 "모든 구성에서 비활성"으로 보고된다. tree-sitter가 놓쳤던 함수 11개가 모두 잡혔다.

**대상별 결과 (2026-09-28, 리뷰 반영 후).** compile DB는 Expat·TinyXML2는 `uvx cmake ... -DCMAKE_EXPORT_COMPILE_COMMANDS=ON`(Expat은 `-DCMAKE_POLICY_VERSION_MINIMUM=3.5` 필요), 7-Zip은 `uvx compiledb -n make -f ../../cmpl_mac_arm64.mak`로 빌드 없이 만들었다.

| 대상 | 시간 | 파싱 | 1차 Clang 기준 목록 | 추가 함수 | 비활성 보고 | 매크로 본문 |
|---|---:|---:|---|---:|---:|---:|
| Expat R_2_5_0 `lib/` | 2.8초 | 44 | 283/283 | 15 (전부 다른 구성) | 31 | 4 |
| TinyXML2 10.0.0 | 2.9초 | 20 | 395/395 | 3 (전부 다른 구성) | 0 | 0 |
| 7-Zip 26.01 `C/` | 21.4초 | 485 | 643/643 | 114 | 208 | 16 |

7-Zip 기준 목록 중 3개는 끝 줄이 같고 시작이 7~8줄 앞선다. 속성 줄(`Z7_NO_INLINE`, `static`, `#ifdef ...ATTRIB`)까지 선언에 포함했기 때문이다. Expat의 매크로 본문 4개는 1차 추출 때 미평가로 기록한 4개와 같다.

**CodeQL 대비 (조사 때의 CodeQL 2.27.1 결과와 파일·끝 줄 단위로 대조).**

| | 빌드 추적 | 651 | 648 | 3 | 263 |

CodeQL에만 있는 것 중 15개는 매크로가 본문을 만든 함수로, Sift는 본문이 원문에 없어 "매크로가 만든 본문"으로 보고한다. 나머지 2개는 CodeQL 빌드 없음 모드가 서로 다른 파일의 `main` 두 개를 한 함수로 합쳐 위치를 뒤섞은 결과다. Sift에만 있는 것은 다른 구성에서만 보이는 함수와, 빌드 추적에 들어가지 않은 파일(`C/Util/` 등)의 함수다.

**리뷰로 고친 것 (2026-09-28).** C++ friend 함수와 템플릿 부분 특수화의 메서드가 빠지고 보고도 안 되던 문제, compile DB 밖 C++ 파일이 C 플래그를 빌려 파싱에 실패하면 스캔 전체가 중단되던 문제, 들여쓴·탭·중첩 `#ifdef`에서 매크로 켜고 끄기가 동작하지 않던 문제, 비활성 보고에 지시문만 있는 줄과 이미 평가하는 함수 본문이 섞이던 문제(7-Zip 723 → 208), Jev가 같은 상태를 동시에 두 번 보내던 문제, 잘린 캐시 줄 때문에 재개가 실패하던 문제.

## 관계 추출 도구 — 기록

CodeQL CLI 2.27.1로 C/C++·Rust·Go·Python 스냅샷의 데이터베이스와 직접 호출 관계를 얻었다. 7-Zip 함수 포인터와 urllib3 동적 메서드 호출은 미해결. C 파일 하나를 Clang AST로 확인한 결과 직접 호출·필드 접근 근거는 CodeQL 없이도 얻을 수 있었다. 기록: [codeql-pilot](archive/second-pass/codeql-pilot/README.md).
