# 첫 비교 실험은 Jev를 전수 순위화 한 단계에 사용한다

> 2026-10-02 [ADR 0025](0025-restore-second-jev-stage.md)로 대체했다. 이 구성은 Sift 주 비교군이 아니라 1차만 남긴 절제 비교군으로 보존한다.

2026-10-01 결정. 첫 비교 실험에서 Jev는 대상의 분석 유닛을 평가해 에이전트의 조사 순서를 만드는 역할 하나를 맡는다. 유닛별 모델 요청은 여러 번 발생할 수 있다. 여기서 한 단계는 API 호출 횟수가 아니라 연구 과정에서 Jev가 개입하는 지점의 수를 뜻한다.

실험 흐름은 **에이전트의 대상별 Sift 구축 → 전수 목록화 → Jev 순위화 → 에이전트의 저장소 전체 조사 → 독립 검증과 PoC 재현**으로 둔다. Sift군에는 미리 계산한 Jev 점수나 순위를 주지 않는다. 같은 에이전트가 Sift 구축 방법과 공통 재료, Jev 사용 수단을 받아 실행 중에 순위를 직접 만든다. 구축과 Jev 실행에 든 시간·요청·토큰은 Sift군의 종단 비용에 포함한다.

에이전트는 자신이 만든 순위가 가리킨 유닛에서 출발하되 호출 관계, 데이터 흐름과 설정을 자유롭게 추적할 수 있다. 첫 비교에서는 관련 코드 묶음을 Jev로 다시 평가하거나 조사 도중 후보를 Jev로 재순위화하지 않는다.

이 선택은 SystemOne 순위의 기여를 다른 단계의 효과와 분리하기 위한 것이다. 지금까지 관련 코드 문맥을 붙인 2차 평가는 함수만 평가한 방식보다 판별력이 좋아지지 않았고, 같은 코드 양 예산에서 1차 순위보다 적은 버그에 닿았다([설계의 근거와 한계](../../DESIGN.md#6-근거와-한계)). 깊은 관계 추적은 첫 실험에서 에이전트가 맡는다.

이 결정은 최종 Sift를 한 단계로 제한하지 않는다. 다음 현상이 반복되면 다단계 Jev를 후속 가설로 검토한다.

- 유닛 하나의 코드로 판단할 수 없는 사례에서 한 단계 순위가 반복적으로 실패한다.
- 에이전트가 조사 중 만든 후보가 많아 후속 선별 비용이 병목이 된다.
- 첫 조사 결과를 이용한 재순위화가 필요하다는 관찰 가능한 근거가 생긴다.

후속 비교에서는 한 단계와 다단계 방식의 총 Jev 비용과 에이전트 예산을 같게 맞추고, 독립 검증과 PoC 재현 성과를 비교한다. 한 단계의 실패를 정의하지 않은 채 다단계 호출을 추가하지 않는다.
