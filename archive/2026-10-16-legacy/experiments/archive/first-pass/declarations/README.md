# 1차 입력 범위: 함수 본문과 선언

앞선 [파일 전체 표본 실험](../contrastive/README.md)에서 단순 조사 가치 질문이 상위 10% 예산의 6개 취약점 기전 중 5개를 찾았다. 함수 밖 정보가 1차 순위를 개선하는지 확인하되, 2차의 관련 코드 분석과 경계를 유지한다.

## 경계

- **1차:** 모든 함수를 각각 Jev로 평가한다. 대상 함수 본문을 반드시 포함한다. 비교 입력에는 그 함수를 해석하는 데 필요한 **파일 내부 선언**만 더한다: 직접 참조한 모듈 import·할당, 소속 클래스 및 바로 위 부모 클래스의 헤더·클래스 속성. 다른 함수 본문은 넣지 않는다.
- **2차:** 1차를 통과한 함수에서 시작해 호출·참조·공유 상태 관계를 따라 다른 함수 본문을 수집하고 재선별한다. 관련 코드 묶음 방식은 [2차 구조 비교](../../second-pass/README.md)의 실험 대상이다.
- **3차:** 남은 후보를 심층 분석하고 근거를 검증한다.

이 구분은 **입력의 내용과 적용 범위**로 정한다. 1차에는 선언을 모든 함수에 동일한 규칙으로 붙이고, 2차에는 선별된 함수에만 다른 함수 본문과 관계를 붙인다. 특정 취약점이나 목표 함수의 라벨을 보고 선언을 골라 붙이지 않는다.

## 비교 설계

[`context_scope.py`](../context_scope.py)는 [`contrast_holdout.json`](../contrast_holdout.json)의 여섯 취약 버전 파일에서 뽑은 277개 함수를 그대로 사용한다. `function` 입력은 지난 실험과 같은 `Function: ...\nCode:\n<본문>`이다. `declarations` 입력은 같은 문자열 뒤에 최대 30,000자의 위 선언을 붙인다. 선언은 AST로 선택하며, 길이 초과로 누락한 선언 수와 실제 입력 해시를 기록한다. 추가한 코드에 다른 함수 본문이 없음을 추출 규칙으로 보장한다.

두 입력에 **동일한** `review_worth_plain` 질문과 `jev-1.13.0`을 사용한다. 요청당 질문은 하나다. 입력·반복 순서를 고정 시드로 섞어 각 함수·입력 조합을 세 번 평가한다. 함수별 점수 내림차순, 동점은 유닛 ID 오름차순으로 정렬하고, 파일별 상위 10%의 목표 함수 도달 수를 주요 지표로 사용한다. 상위 35.5%, 사례별 목표 함수 순위, 입력 토큰, 오류와 선언 누락을 함께 기록한다.

이 여섯 사례는 **이미 질문 개발 결과를 확인한 표본**이다. 따라서 이번 결과는 입력 경계의 진단에 쓰고, 개선이 보여도 곧바로 제품의 1차 입력으로 채택하지 않는다. 이후 새로운 프로젝트·취약점과 디컴파일 코드에서 같은 입력 규칙을 다시 확인해야 한다. 목표 함수 외 나머지 함수는 안전하다고 라벨링하지 않았으므로 정밀도는 계산하지 않는다. 상위 비율 실험은 제품의 점수 임계값을 정하지 않는다.

## 실행 및 결과

`python3 experiments/first-pass/context_scope.py prepare`로 함수 수, 추가 선언 길이와 누락을 확인한다. `run --workers 12`는 각 결과를 즉시 Git 제외된 `experiments/first-pass/runs/context-scope/responses.jsonl`에 남기며 같은 입력·질문·모델 해시의 성공 건만 재사용한다. 완료 후 `report`로 순위와 입력량을 비교한다.

277개 함수 × 입력 2종 × 반복 3회 = **1,662건**을 모두 채점했다. 오류와 선언 누락은 없었다. 전부 응답 모델 `jev-1.13.0`이었다.

| 입력 | 상위 10% 도달: 반복 1·2·3 | 상위 35.5% 도달: 반복 1·2·3 | 입력 토큰 합계 |
|---|---:|---:|---:|
| 함수 본문만 | 5·5·5/6 | 5·5·5/6 | 329,697 |
| 함수 본문 + 선언 | 5·5·5/6 | 5·5·5/6 | 438,432 |

선언 입력은 108,735토큰(약 33%)을 더 썼으나 새 기전에 도달하지 못했다. Werkzeug 쿠키 목표 함수는 본문 단독 2~3위에서 선언 추가 2위로, urllib3 압축 스트림의 `HTTPResponse.read`는 4위에서 1~4위로 움직였지만 양쪽 모두 이미 상위 10%에 있었다. Django `FileInput.value_from_datadict`는 본문 단독 95개 중 59~66위, 선언 추가 55~62위로 여전히 10개 선발 예산 밖이었다. 이 함수에 추가한 선언은 483자이며, 다른 함수 본문은 없다.

따라서 이 표본에서 **선언을 모든 함수에 추가할 근거는 없다.** Django 누락은 클래스·모듈 선언만 더해서 해결되지 않았다. 다른 함수의 동작이나 호출 계약이 필요한지 보려면 2차 실험에서 확인해야 한다. 다만 2차는 1차를 통과한 함수에서 시작하므로, 목표 함수가 1차에서 탈락해도 다른 통과 함수의 관계를 통해 그 취약 동작에 닿을 수 있는지 함께 측정해야 한다. 이번의 목표 함수 순위만으로 종단 발견율을 단정할 수 없다.
